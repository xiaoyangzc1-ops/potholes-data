# 使用指南（如何使用本仓库）

> 你问的“我应该怎么使用”，可以按下面 4 步走。

## 1. 先看什么
1. 先读阶段一方案：`docs/phase1-方案设计.md`
2. 再看本文件：`docs/使用指南.md`

这样你会先理解“做什么”，再看“怎么做”。

---

## 2. 当前仓库状态
当前仓库是**阶段一：方案设计完成**，还没有进入完整编码实现。

你可以把它当成：
- 需求基线（功能范围）
- 技术蓝图（数据结构、路由、算法）
- 实施清单（按阶段开发）

---

## 3. 推荐落地方式（按阶段）

### 阶段二（先做最小可运行）
目标：让小程序先跑起来。

1. 初始化小程序工程目录（`miniprogram/`）
2. 配置 `app.json` 页面路由
3. 实现 3 个页面：
   - 登录页 `pages/login`
   - 首页 `pages/index`
   - 训练组页 `pages/team`
4. 在微信开发者工具中运行，确认可打开页面

验收：
- 能登录
- 教练可创建训练组
- 学生可通过邀请码加入

### 阶段三
目标：完成“每周任务 + 手动填表”。

1. 实现创建周任务页 `pages/createTask`
2. 实现填表页 `pages/fillSchedule`
3. 接入 `weekly_tasks`、`weekly_schedules` 的读写服务
4. 保证“仅被 @ 成员参与填写与计算”

### 阶段四
目标：完成汇总和推荐算法。

1. 新增汇总页 `pages/summary`
2. 实现共同空闲时间算法
3. 实现推荐训练时间算法
4. 展示未提交名单

### 阶段五
目标：发布最终训练安排。

1. 新增发布页 `pages/publishTraining`
2. 教练选择时间并发布
3. 学生首页展示最终训练时间

### 阶段六、七（第二版）
目标：图片识别能力。

1. 先用 mock 识别结果
2. 强制“识别结果先确认，再写入周表”
3. 后续再替换成真实 OCR / 多模态服务

---

## 4. 你现在可以直接做的事

如果你是产品/教练：
- 直接评审 `docs/phase1-方案设计.md`，确认字段和流程是否要改。

如果你是开发：
- 从阶段二开始建工程；
- 每完成一个阶段就对照文档里的验收标准打勾；
- 不要跳阶段一次性写完（后期返工成本高）。

---

## 5. 常见问题

### Q1：为什么没有直接给完整代码？
因为原始需求明确要求“先方案、分阶段实现”，避免一开始把 OCR/聊天解析等复杂模块硬写死。

### Q2：我想马上看到可运行版本怎么办？
按上面的阶段二先做最小可运行（登录/首页/训练组），这是最稳妥的起步方式。

### Q3：历史周次会不会被覆盖？
不会。方案里要求周任务按 `team_id + week_start_date` 独立管理，且周表按任务维度独立存储。
